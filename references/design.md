# 技术选择与复用评估（2026-10-24）

选择：可移植 `SKILL.md` + 标准库预算核算。保留官方 MCP SDK 作为可选的只读直连路径。无需服务器、数据库或额外模型 API key。

| 方案 | 评估 | 决定 |
|---|---|---|
| 只有提示词 | 依赖少，但预算金额、失败报价和上下文一致性缺少确定性检查 | 增加小型标准库核算器 |
| 原生 MCP + 核算脚本 | 直接复用客户端工具、实现少，保留真实 schema 与逐人需求判断 | 作为主路径 |
| 官方 SDK 直连 | 支持协议协商、JSON/SSE、会话及跨源重定向防护，避免自写协议客户端；依赖树较大 | 只作为可选辅助，不影响已连接宿主的使用 |
| 独立实时网页与后端 | 需新增凭据托管、模型接入和部署成本，超出已确认形式 | 不采用 |
| 静态展示试玩页 | 用户已确认新增；不需要 Token、后端、模型或第三方运行依赖 | 增加 `docs/`，模拟互动与真实历史记录分开标记 |

## 外部依赖

官方仓库：https://github.com/modelcontextprotocol/python-sdk 。许可证 MIT；只通过 PyPI 安装，没有复制第三方项目业务代码。当前直接依赖固定 `mcp==2.3.0`、`httpx2==2.16.0`、`jsonschema==4.26.0`；API 已按对应版本文档、Context7 和已安装包签名核对，并经真实服务调用验证。SDK 2.x 与 1.x API 有差异，因此固定版本。

评估关注实际接口、发布版本、依赖元数据和运行输出，没有用 Star 数判断质量。SDK 有多项服务端/加密等传递依赖；这是可选直连方式的成本。主 Skill 与核算脚本无第三方运行依赖。本次未执行完整软件供应链或依赖漏洞审计，后续升级需重新测试；MIT 不代表无安全风险。

官方参赛声明按活动仓库要求原样附入，独立于项目原创脚本。不复制其他参赛项目的实现。项目所有者已确定原创代码与技能指引以 MIT 许可证发布，并确认参赛声明和活动规则。官方声明按要求保持原文。

## 网页参考与选择

参考了 [dayebishouji/mcd-random-meal](https://github.com/dayebishouji/mcd-random-meal) 的“模拟试玩 + 真实联调记录 + Skill 安装入口”展示思路。检查时该仓库采用 MIT 许可证、未归档、于 2026-10-24 更新，文档和目录显示静态前端没有运行依赖；这些信息不能代替完整安全或维护审计。本项目未复制其代码、图片、餐品数据或文案，交互、预算模型和视觉均独立实现，插画由内置 image_gen 生成，提示词见 `assets/image-prompt.md`。

选择标准 HTML/CSS/ES modules，使用浏览器和 Node.js 标准能力；不引入 React、打包器或外部字体。相较框架方案，当前的三套模拟方案、复制和筛选不需要额外依赖。公开页面采用 Sites 静态托管，源码也保留在原参赛 GitHub 仓库的 `docs/` 中，便于其他静态服务托管。实时 Skill 及其已有查询链路保持不变。

演示只有三种预设组合，不保证全菜单最优，不代表真实供应、热量、过敏原安全或当前价格。模拟预算上限 2000 元、人数 1—6 人，金额精确到分。已知实际核价证据仍仅来自原先记录的真实调用。

## 适配与局限

- 客户端的 Skill 导入、MCP 命名及环境变量语法不同；配置模板不是所有客户端的通用可执行配置。
- 实时服务本次发现 35 项工具，文档为 33 项；到店 `beCode`、门店搜索参数也有差异，以当前 schema 为准。
- 优惠券、门店、时段及个性化价格随账户和时间变化；只保留脱敏验收摘要。
- 预算脚本不能替代口味、份量、过敏或营养判断；未知信息须明确保留。
- 原生宿主可能显示所有麦当劳工具；Skill 的范围限制属于行为约束。辅助直连脚本则从命令入口和调用函数两处限制只读白名单。
